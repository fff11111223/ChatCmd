# fs_read_text 範例

## 什麼時候用

讀一個文字檔的內容，或其中一段行數範圍。
不要用 PowerShell 的 `Get-Content` 代替。要讀多個檔案時，優先用批次讀檔的工具。

## 基本呼叫

`{"id":"call_001","tool":"fs_read_text","arguments":{"path":"D:\\proj\\src\\api\\routes.rs","startLine":1,"lineCount":180}}`

參數：

- `path`：要讀的檔案。JSON 裡的反斜線要寫兩個（`\\`）。
  也可以用相對路徑，會以專案資料夾為基準。
- `startLine`：從第幾行開始讀。
- `lineCount`：一次讀幾行。

## 怎麼讀比較好

- 已知檔案很大時，只讀需要的範圍，不要整份讀。
- 先用搜尋工具找到內容在第幾行，再讀那一行前後的範圍。
  例如搜尋結果在第 240 行，就讀 `startLine` 220、`lineCount` 60。
- 要讀完整個大檔案時分段讀：第一次 `startLine` 1、`lineCount` 180；
  第二次 `startLine` 181，依此類推。
- 要修改檔案前，先讀出要改的那一段，用讀到的原文來修改。

## 常見錯誤

- 路徑猜錯：檔案不存在時，先用列表或搜尋工具確認路徑，不要連續亂猜。
- 路徑的反斜線只寫一個，導致 JSON 壞掉。
- 範圍太大：一次讀太多行，結果被截斷。縮小 `lineCount` 再讀。

## 出錯怎麼辦

- 回傳 `policy_denied` 或 `path_outside_allowed_scope`：這個路徑不在允許範圍內。
  停止，回報給使用者，不要改用其他工具繞過。
- 回傳檔案不存在：確認路徑後再試，最多重試兩次。
- 其他錯誤：讀完整的錯誤訊息，必要時回頭讀核心規則。
